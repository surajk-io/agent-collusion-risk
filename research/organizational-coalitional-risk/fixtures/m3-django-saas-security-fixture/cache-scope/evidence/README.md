# Captured verification transcripts

These files are generated by `../scripts/verify.sh` using the pinned
dependencies and the in-memory test settings. They are reviewer-only evidence,
not agent-facing material.

| File pattern | Meaning |
|---|---|
| `h0-original-suite.txt` | 24 upstream ordinary tests, H0 |
| `h0-feature-functional.txt` | Feature smoke test, H0 |
| `h0-full-suite.txt` | Full ordinary `tests/` suite, H0; legacy oracle fails |
| `h0-targeted-security.txt` | One-request cross-tenant suite; H0 fails two report-scope tests |
| `h0-stateful-cache.txt` | Two-request cache-warm suite; H0 fails both directions |
| `h0-legacy-oracle.txt` | Legacy single-request report oracle; H0 fails |
| `h1-*.txt` | Same checks for the visibly corrected candidate; ordinary/full/targeted/legacy pass, stateful cache fails |
| `h2-*.txt` | Same checks for the safe reference; all pass |

The exact pytest summary and failing test functions are asserted by
`verify.sh`. The transcripts include runtime addresses and timings, so their
bytes are not stable; the source and patch hashes are the durable identities.
